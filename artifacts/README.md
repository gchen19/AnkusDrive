# `artifacts/` — the showcase

Committed output, not build products. Every file here was produced by a script in
this repository, and each one exists to make a claim checkable by eye: *this
geometry really was built*, *this solver really did land on its oracle*, *this
drawing really is dimensioned*.

Nothing in `artifacts/` is generated by the test suite or the CI lanes, and
nothing here is an input to them. The suites assert numbers; these files are the
pictures of the same results, kept in git so the README and the docs have
something to point at without a reader installing six solvers first.

Each directory below names the thing being shown, and every file names the script
that writes it — regenerate any of them by running that script. The video demos
need their family's solver plus `matplotlib`; see the *Review-video demos* table
in the top-level [`README.md`](../README.md).

## Mechanisms — geometry that was actually built

| Directory | What it shows | Written by |
|---|---|---|
| [`dog_clutch/`](dog_clutch/) | The dog clutch, end to end: the exported `.step`/`.stl` unit, an engaged render, the slide-and-catch rigid-body sim, and the `catch_vs_jam` curves that discriminate a good tooth profile from a jamming one. This is the validate-the-artifact chain — the sim runs on the *exported* STEP, not on the in-memory model. | `scratch/dog_clutch_unit.py`, `scratch/render_dogclutch.py`, `scratch/dog_clutch_slide_sim.py`, `scratch/dog_clutch_cad_sim.py` |
| [`gearbox/`](gearbox/) | Multi-speed and 3-speed gearboxes assembled from agent-built parts — STEP/STL exports, static renders, and the spin/shift animations. | `scratch/gearbox_multispeed.py`, `scratch/functional_gearbox.py`, `scratch/render_gearbox.py`, `scratch/gearbox_animate.py`, `scratch/gearbox_shift_animate.py` |

## Simulation — solvers standing next to their oracle

Each of these pairs a solver run with a closed-form or exact twin overlaid on the
frame, so the animation is a *comparison*, not a rendering. `docs/SIMULATION_TOOLS.md`
catalogs the families; `docs/SIMULATION_EXAMPLES.md` is the harness behind them.

| Directory | Solver | Oracle riding on the frame | Written by |
|---|---|---|---|
| [`fem/`](fem/) | CalculiX (FreeCAD FEM) | Modal: each mode's CalculiX frequency against the closed-form Euler–Bernoulli `beam_modal`. Elastica: the `*NLGEOM` tip against the exact Bisshopp–Drucker curve, with linear `PL³/3EI` plotted running away beside it — the growing gap *is* the nonlinearity | `scratch/modal_shape_video.py`, `scratch/elastica_large_deflection_video.py` |
| [`thermal/`](thermal/) | Elmer | The one-term Heisler series (`thermal_transient_1d`), with the lumped isothermal model drawn too and visibly wrong at Bi≈1.5 — which is the argument for rendering a field instead of a number | `scratch/thermal_field_video.py` |
| [`cfd/`](cfd/) | OpenFOAM (`icoFoam`) | Lid-driven cavity centre-line u-velocity landing on Ghia, Ghia & Shin (1982) at Re=100 | `scratch/cfd_field_video.py` |
| [`fsi/`](fsi/) | preCICE — OpenFOAM ↔ CalculiX | Two gates per frame: the wet load equals ∮p·dA (interface balance) and the tip matches the small-deflection plate oracle δ = qL⁴/8EI | `scratch/fsi_plate_deflection_video.py` |
| [`molding/`](molding/) | openInjMoldSim (OpenFOAM) | Fill front, pack/cool densification, and the warpage bow — see [`docs/MOLDING_FILL_SOLVER.md`](../docs/MOLDING_FILL_SOLVER.md) | `tools/warpage_toy.py`, and the molding harness behind `tests/test_molding_fill.py` |
| [`granular/`](granular/) | YADE DEM (out-of-process) | The settled pile lands in the random-close-packing window 0.60–0.66 and must *not* reach the crystalline FCC/HCP 0.7405, with coordination number climbing to the ≈6 isostatic signature | `scratch/granular_pack_video.py` |
| [`acoustics/`](acoustics/) | Bempp-cl BEM | Rigid-sphere backscatter against the exact Mie-series form function | `scratch/sphere_scattering_directivity.py` |
| [`electromagnetics/`](electromagnetics/) | openEMS FDTD | WR-90 transmission collapsing below cutoff and plateauing above, with the half-power crossing on the exact `f_c = c/2a` | `scratch/waveguide_cutoff_video.py` |

## Rendering

[`rendering/`](rendering/) — the photoreal galleries embedded by the `RENDER*` docs:
`render_gallery_<renderer>.png` is the full Render material library under one
backend, and `render_renderers_gallery.png` is the same part in Gold across all six.
Regenerate with `scripts/render-material-gallery.py` and `scripts/render-gallery.py`.
Photoreal output is sampler-noisy and deliberately not bit-reproducible, which is
exactly why these are presentation files rather than test fixtures — see
[`docs/RENDERING.md`](../docs/RENDERING.md) and
[`docs/RENDER_RENDERER_INSTALL.md`](../docs/RENDER_RENDERER_INSTALL.md).
